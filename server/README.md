# Автоматические заявки HomePorte

Квиз и быстрая форма отправляют JSON на `/api/leads` того же сайта. Сервер сохраняет заявку в SQLite и отвечает 202. Фоновый обработчик отправляет её в Telegram. Копирование текста и переход в Telegram посетителю не нужны.

## Локальный запуск

Нужен Node.js 24 или новее. Внешних npm-зависимостей нет.

1. Скопировать `.env.example` в `.env`, если файла ещё нет. Вписать токен и ID чата получателя. Не вставлять токен в HTML/JS или команды shell.
2. Получатель должен первым запустить бота в Telegram. Для группы добавить бота и разрешить ему отправку сообщений.
3. `chmod 600 .env` и `npm start`.
4. Открыть `http://127.0.0.1:8766`. `npm test` проверяет валидацию, защиту приватных файлов, повторные запросы, сохранение и повторную доставку на подставном Telegram без реальных сообщений.

Не запускать обычный `python -m http.server` в корне: он может раздать `.env` и базу. Встроенный сервер обслуживает только явно разрешённые публичные файлы.

## VPS и HTTPS

GitHub Pages исполняет только статические файлы и не запускает этот сервер. Для автоматической отправки перенести сайт вместе с сервером на VPS. На публичном домене energostatusby-beep.github.io формы предлагают явную ручную передачу: скопировать подготовленный текст и открыть Telegram менеджера. Сообщение об автоматическом приёме при этом не показывается. На VPS используется серверная отправка без ручного копирования.

1. Скопировать проект без `.env` и `var` на VPS; секреты перенести отдельно защищённым соединением. Указать в `.env` `ALLOWED_ORIGINS=https://ваш-домен` (точный адрес, без завершающего слеша; несколько адресов через запятую).
2. Установить Docker с Compose, запустить `docker compose up -d --build`.
3. Установить Caddy на хосте, использовать `Caddyfile.example`, заменив домен; направить DNS на VPS. Открыть внешние порты 80/443. Порт 8766 остаётся привязанным к localhost.
4. Caddy выдаёт HTTPS-сертификат и перезаписывает X-Real-IP. `TRUST_PROXY=1` допустим только за таким прокси при недоступном снаружи порте приложения.
5. Проверить `/api/health` и отправить тест через каждую форму. `acceptingLeads=true` означает наличие настройки, но не подтверждает доступность Telegram или правильность чата.

Запускать **один экземпляр** приложения на одну базу. Том `leads` хранит очередь между пересборками. `docker compose down -v` удалит её — эту команду для обновлений не использовать. При переносе уже работающей установки остановить приложение, сохранить весь том (SQLite и WAL), перенести его и затем запустить новый экземпляр. Не запускать старый и новый одновременно. Резервные копии содержат контакты; хранить их с ограниченным доступом.

## Надёжность и ограничения

- Сервер проверяет поля, размер тела, источник запроса и скрытое антиспам-поле. Лимиты: 10 запросов с IP в час, 60 в минуту суммарно; очередь ограничена 1000 ожидающими заявками. Это базовая защита, а не защита от распределённой атаки.
- Повтор с тем же идентификатором не создаёт новую заявку; одинаковые данные также объединяются в пределах 10 минут. Изменённые данные под старым ID отклоняются.
- Telegram недоступен: заявка остаётся в базе, повторы идут с увеличением интервала до часа. Ошибки токена/чата тоже не удаляют заявку. После исправления настроек перезапустить сервер; доставка повторится в течение часа.
- Подтверждение на сайте означает сохранение, а не доставку в Telegram. При сетевой ошибке форма сохраняет введённые данные и предлагает повтор.
- Telegram не поддерживает ключ идемпотентности sendMessage. Если сообщение принято, но ответ потерян, при повторе возможен дубль. В сообщении сохраняется номер заявки при повторе. Нумерация начинается с №1 каждый календарный месяц по Europe/Minsk; месяц определяется при приёме заявки. Счётчик хранится в базе и не сбрасывается при перезапуске или удалении старых заявок. Внутренний UUID остаётся только в базе и служебных логах.
- Доставленные заявки удаляются из локальной базы через 30 дней (проверка каждый час); ожидающие доставки не удаляются. Сообщения в Telegram и резервные копии автоматически не удаляются.
- Логи содержат только ID заявки и код ошибки, без телефона, текста и токена. `.env` и база исключены из Git и Docker-контекста; HTTP к ним закрыт.
- `docker compose logs --tail=100` — смотреть доставку и отложенные попытки. Следить за свободным диском и регулярно делать защищённые резервные копии.

Для ротации токена обновить `.env` и пересоздать контейнер: `docker compose up -d --force-recreate`. Токен не передавать в аргументах команд, не публиковать и не добавлять в репозиторий.
